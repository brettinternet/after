# Research behind AFTER

Primary product pages, documentation, and READMEs were inspected October 2, 2026. This desk review is not a hands-on benchmark or exhaustive market/patent survey. Product claims are attributed; performance, maturity, accuracy, adoption, and novelty were not verified. Search aided discovery; GitHub READMEs were retrieved with `gh api`.

## Conclusion

Summaries, semantic groups, tours, flow graphs, paired execution, provenance, review memory, and freshness all have prior art, often combined with evidence and human decisions.

The narrower idea worth testing is an **example-first review interface on local Git changes**, with optional expectation pins that reopen when their basis changes. The distinction is the starting interaction and low setup cost—not a new verification technique. I did not establish that no existing tool offers the exact workflow. No novelty or patent claim is intended.

## Other ideas that are not the wedge

| Idea                                           | Why not start there                                                                                                                         |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Spatial repository atlas                       | Large graphs are hard to scan and can imply unsupported causal knowledge. Use a short expandable path after selecting an example.           |
| Movie of every agent action                    | Useful for attribution and rollback, but often slower than inspecting the final consequence; checkpoint products already cover this.        |
| Inbox with only human decisions                | Can hide missing work. Prioritize questions while retaining the full source inventory and unknowns.                                         |
| Automatically split changes into ideal commits | Intermediate states may not be valid, and sequencing does not explain behavior; Differential explores synthetic review stacks.              |
| Universal counterfactual simulator             | Arbitrary apps need services, state, credentials, timing, and environment control. Start with supported experiments and available evidence. |
| Second agent that certifies the first          | Model agreement is not independent execution evidence. Display agent evidence and limits instead.                                           |

## Research limits and next work

No products were installed; performance, implementations, patents, or user views were not evaluated. Pages change quickly; small and hackathon projects are not treated as mature competitors.

Before expanding the engine, use Limn, Diffcore, a leading guided PR interface, and a bound-evidence verifier on the same repository. Try the exact **pin → dependency edit → re-review** workflow and observe engineers doing it today. If an existing product handles it well, integrate with it or choose another wedge.

The key unanswered questions are whether useful examples exist at first use, and whether conservative freshness reduces repeated review without being misleading or noisy. The presentation does not answer either question.
